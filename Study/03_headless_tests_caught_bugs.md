# 03. 창 없는 테스트가 실제로 잡아 준 버그들

> 질문: 화면을 눈으로 보면 되는데, 굳이 창 없이 도는 테스트를 왜 만드나?
>
> 짧은 답: **눈은 "지금 이 장면"만 본다.** 테스트는 순서 · 시간 · 경계값처럼 한 장면에 안 보이는 것을 본다.
> 이번 P2에서만 실제로 세 번 잡았다.

실행: `godot --headless --path Game -s res://tests/run_tests.gd` (러너: [`Game/tests/run_tests.gd`](../Game/tests/run_tests.gd))

---

## 잡은 버그 1 — 그리는 순서 (연구소 형광등)

`test_blend_modes`가 실패: "꺼진 형광등 관이 어둡게 하는 층(곱하기) **위**에 있다".
`move_child()`로 순서를 "고치는" 줄이 오히려 관을 위로 올리고 있었다. 화면에선 관 하나가 살짝 밝을 뿐이라 눈으로는 놓치기 쉽다.

## 잡은 버그 2 — 테스트 러너 자신

스크립트에 오류가 나서 테스트 함수가 중간에 멈춰도, 러너는 실패가 0개니까 **통과**로 셌다.
→ 테스트마다 검사가 한 번이라도 돌았는지(`checks`) 세고, 0이면 실패로 바꿨다. 컴파일이 안 된 테스트 파일도 실패로 센다.
교훈: **테스트 도구도 테스트해야 한다.** "전부 통과"가 거짓말일 수 있다.

## 잡은 버그 3 — 도장 찍는 동안 바뀐 종이 (판독)

평가 키를 누르면 `StudySession.submit()`이 더미에서 카드를 빼므로, 도장이 찍히는 0.8초 동안 화면은 이미 **다음 단어**를 그렸다.
스크린샷에서 발견 → `ReaderModel.shown_id`로 "판독기 위의 카드"를 따로 들고, 테스트(`test_reaction_time_and_grade`)에 한 줄 추가해 다시는 안 생기게 했다.

## 무엇을 테스트하고 무엇을 눈으로 보나

| 테스트 (빠르고 반복 가능) | 스크린샷 (`--shot`) |
| :--- | :--- |
| 등급표 24칸 (`test_classify_table`) · 4시 하루 경계 · 2장 뒤 / 4장 뒤 | 위치 · 색 · 글자 크기 · 층이 시안과 같은가 |
| 모르겠음 → 같은 카드 2장 뒤 | 모자이크가 '점무늬'로 보이는가 |
| 평가 전엔 일어설 수 없음 · 창 포커스 잃으면 처음부터 | 헤드가 글자 위를 지나가는가 |

## 직접 해 볼 것

- `Fsrs.classify`에서 `2.5`를 `3.0`으로 바꾸고 테스트를 돌려 어느 칸이 깨지는지 보기 (그 칸이 CORE_LOOP §2.1 표의 어디인지 찾기).
- 새 `class_name`을 만든 뒤 `--import` 없이 테스트를 돌려 보기 — 왜 "Identifier not declared"가 나는지 (전역 클래스 캐시).
