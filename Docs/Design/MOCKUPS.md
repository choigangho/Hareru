## M-0. 스타일 샘플

**목적**: 대량 제작 전에 화풍 하나를 고정. (소유자: v3 사실적 비율 거부, v1 3등신 선호, 주임은 더 귀엽게)

보여 줄 것:
- [ ] 주임 단면 스프라이트 48×48 대기 1프레임 + 대사 초상 96×96 `기본`
- [ ] 주인공 단면 스프라이트 48×48 + 초상 96×96 `기본`
- [ ] 소품 1개: 크림 레트로 CRT (화면 켜짐, 녹색 형광) — 담쟁이 한 줄
- [ ] 팔레트 칩 30색 (Phosphor 28 + 극값) + 캐릭터 전용으로 추가한 색
- [ ] 같은 그림을 ×2 · ×4로 나란히 (화면에서의 실제 크기 확인)

확정 질문:
1. 3등신 비율 · 머리 크기가 v1 느낌인가?
2. 주임이 충분히 귀엽고 예쁜가? (눈 크기 · 안경 · 단발)
3. 주인공의 차가운 회청색 옷이 연구소 안에서 어색하지 않은가?
4. 초상 96×96이 대사창에 적당한가, 64가 나은가? (결정 A-3)

## M-1. 연구소 단면

**목적**: 기본 화면. 게임 시간의 절반 이상을 보는 곳.

보여 줄 것 (비 오는 오후 1장 + 같은 구도 밤 1장):
- [ ] 건물 단면: 위층 연구실(밝음) · 나선 계단 · 지하 「源」(어두운 실루엣, 잠김)
- [ ] 연구실 안: 주임 책상(CRT · 책 더미) · 신입 책상(판독기 덮개) · 천장 누수 + 양동이 · 쓰러진 KURO · 게시판 「常駐人員」 · 구석 CRT 더미 + 담쟁이 · 금 간 창(왼쪽 위)
- [ ] 벽의 물건 3개: 연구 장부(숫자판) · 기록 클립보드 · 배전반 — **탭 대신 이것들을 누름** (결정 C-1)
- [ ] 주임 · 주인공 스프라이트가 서 있는 모습 (크기 비율)
- [ ] **앉아 있는 인물**: 주임이 자기 의자에 앉아 책 더미 뒤로 머리끝만 보이는 모습(T-1 첫 컷) · 주인공이 신입 책상에 앉은 모습 — 등받이 · 책상 앞판이 인물 앞에 오는지, 다리가 책상 밑으로 들어가는지 (SLICE_ASSETS §1-2)
- [ ] 빛 2상태 (A-1): **스탠드 전** — 어두운 사무실, 형광등 하나 · CRT 녹색 · 창밖 시안 간판뿐 / **스탠드 후** — 주임 책상 호박 불빛, 실내가 따뜻하게. 같은 구도 2장
- [ ] 밤: 창밖 시안 렉스코드 간판 깜빡 · 스탠드만 켜짐
- [ ] 앞 층 전선 · 담쟁이 (패럴랙스용, 흐리게)
- [ ] "다음 할 일" 표시: 빛나는 점(`ui_hint_dot`)이 책상 위에

확정 질문:
1. 스탠드 전/후의 밝기 차이가 '보상'으로 느껴질 만큼 큰가? 스탠드 전에도 어디를 누를지 보일 만큼 밝은가? (A-1)
2. 화면 아래 상시 콘솔(v3 시안의 원근 버튼)이 없어도 어디를 누를지 알 수 있는가? (C-1)
3. 단면에서 보이는 층 수 — 연구실 + 계단 + 지하 실루엣이면 충분한가?
4. 쇠퇴(누수 · 금 · 먼지) 정도가 '버려진' 느낌이 아니라 '혼자 지켜 온' 느낌인가?

## M-2. 대화 화면

**목적**: D1의 대부분. 대사창이 화면을 얼마나 덮는지 정함.

보여 줄 것 (단면 위에 겹친 상태):
- [ ] 하단 대사창 = CRT 몸체(크림 플라스틱) 안에 녹색 화면 — 초상 96×96 · 화자 이름표 · 대사 3줄
- [ ] 대사창 왼쪽의 클립보드(소유자 v3 아이디어: 모니터 + 클립보드) — 무엇을 올릴지: **선택지 · 오늘 과제 · 입력** 자리로 제안
- [ ] 일본어 줄 예: 「本当(ほんとう)に、来(き)たんですか?」 — 후리가나, 한국어 뜻은 숨김 상태와 펼친 상태 2장
- [ ] 외운 단어 강조 예: 「『わかります』か?」
- [ ] 선택지 2개 (키캡)
- [ ] `확대` 컷 1장: 주임 `난감` 얼굴 ×2 확대가 화면 가운데
- [ ] 타자 중 커서 · "다음" 표시

확정 질문:
1. 대사창 높이 — 단면의 사람 · 물건을 가리지 않는가? (제안: 화면 아래 27% 이하)
2. 초상은 대사창 안(CRT 화면 속) vs 대사창 위로 솟은 바스트업?
3. 한국어 뜻을 여는 방법 (줄 클릭 / `Tab`)이 눈에 보이는가?
4. 대사 글꼴: 픽셀 고딕 vs 매끈한 고딕 (A-4)

## M-3. 판독 장면 (4상태)

**목적**: 핵심 루프. 스파이크 스크린샷을 출발점으로, ART_STYLE_SHEET 기준으로 다시 그린 시안.

보여 줄 것 (같은 구도 4장) — 2026-11-03 탑다운 재단기형으로 다시 그림, 시안 `Docs/Art/Inbox/set2_objects/topdown/_td_4states.png`:
- [x] ① **스캔 중**: 표제어 「名前」 후리가나 없음, 예문 모자이크 절반, 누름대(헤드)가 종이 중간, 손잡이 올림, 키 4개 꺼짐
- [x] ② **판독 직후**: 손잡이 당김, 후리가나 · 뜻 · 번역, 키 4개 램프 켜짐 + 라벨
- [x] ③ **도장**: 「読」 도장 + 3번 키 눌림, 모니터 주임 웃음 — 종이가 처리함으로 가는 움직임은 `코드`
- [x] ④ **2단계 이벤트**: 오른쪽 위 비스듬한 모니터에 주임 `당황` + 인쇄 띠 "…이름. 좋은 단어죠." / ☐ 1단계 이벤트(명판 「見る」)는 글자만 바꾸면 돼서 시안 생략
- [x] 왼쪽 문서 더미 · 오른쪽 처리함 · 뒤 왼쪽 인쇄기 · 오른쪽 위 모니터
- [x] 키 라벨: 모르겠음 · 애매함 · 알고있음 · 쉬움 + 숫자 1~4
- [x] 화면 어디에도 '앱 패널'(평평한 사각 UI)이 없음 — 전부 책상 위 물건
- [ ] 스피커 LED 깜빡 상태 (그림 아직 없음)

확정 질문:
1. 종이 글자: 매끈한 명조가 픽셀 판독기와 어울리는가? (A-4)
2. 키 라벨을 한국어로 둘지, 아이콘/한자(不 · 曖 · 知 · 易)로 둘지?
3. 스캔 헤드 4회 통과가 "10초 뒤엔 다 보인다"로 읽히는가?
4. 판독 중에도 주임이 보여야 하는가 (오른쪽 CRT) — T-2는 옆에서 설명, T-8은 "혼자".

## M-4. 인트로

보여 줄 것:
- [ ] 꺼진 CRT 테두리 안 녹색 타자 글 2줄 + 커서

- [ ] 채용통지서 종이 확대 (「採用通知」 · 기관명 모자이크 · 손글씨 "출근일: 오늘")
