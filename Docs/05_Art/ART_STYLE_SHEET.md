## 1. 화면 · 픽셀 배율

### 1.1 기준 해상도

| 항목 | 값 |
| :--- | :--- |
| 화면 기준 | **1280×720** (16:9) — 스파이크 `project.godot`와 같음 |
| **그림 기준 (아트 픽셀 캔버스)** | **640×360** — 그림 1픽셀 = 화면 2×2 |
| 정수배 | ×2 = 1280×720 · ×3 = 1920×1080 · ×4 = 2560×1440 · ×6 = 3840×2160 |
| 다른 비율 | 슬라이스는 16:9 고정 + 남는 곳은 검은 띠(레터박스). 반응형은 P4 |

왜 640×360인가:
- 흔한 데스크톱 해상도(1080p · 1440p · 4K)가 **전부 정수배**로 나뉜다. (320×180은 글자 · 표정이 안 들어가고, 1280×720 그대로는 Pixellab 제작량이 4배.)
- 3등신 캐릭터(68px 캔버스, 서 있는 키 약 58px)가 화면 높이의 약 16% → 단면 한 층에 2명이 서도 방이 넉넉함. (2026-11-03: 오너가 Pixellab 계정에 만든 캐릭터 크기로 바꿈 — 연구소 단면도 이 크기에 맞춰 다시 그림)

### 1.2 Godot에서 (P2 구현 메모)

- **그림 층**: 640×360 `SubViewport`에 그림 → 최근접 필터로 정수배 확대. 카메라 이동도 아트 픽셀 단위로 맞춤 (반 픽셀 떨림 없음).
- **글자 층**: 대사 · 루비 · 판독 문서 글자는 **화면 해상도(1280×720)** 층에서 그림 → 한자 · 후리가나가 뭉개지지 않음. (글꼴 결정 A-4)
- 창 크기 변경: `stretch/scale_mode = integer` — 정수배만.

### 1.3 카메라 확대 규칙

- 확대는 **정수배(×2)만.** 스파이크의 책상 확대(×2.2)는 단면 그림을 늘려 픽셀이 깨짐.
- **판독 장면(책상)은 단면의 확대가 아니라 별도 그림** — 책상 위를 위에서 내려다본 **320×180 그림을 ×4로 표시**(화면 1280×720). 단면보다 2배 가까이 다가간 근접 화면이라 픽셀이 2배 크게 보이는 게 의도. 종이 글자 · 키 라벨 · 인쇄 띠 글자는 화면 해상도 층에서 그림(§1.2). 전환: 단면에서 책상 쪽으로 ×2 확대 0.4초 → 책상 그림으로 컷(디졸브 없이 '주사선 넘김' 0.15초).

### 3.1 Day 1의 빛 — 스탠드가 켜지기 전과 후

소유자 방향은 **햇빛이 드는 따뜻한 연구소**(v3 피드백)인데, 대본의 Day 1은 **비 오는 오후 → 밤**이고 세계관상 1단계(N5) 하늘은 '흐림 · 비'이다 (GAME_DESIGN §5.1, STORY_BIBLE이 원본). 그래서 Day 1 안의 **책상 스탠드 보상**(N5_SCRIPT T-7 과제 → T-8 설치 「あかるい!」)을 빛의 전환점으로 쓴다.

| 구간 | 대본 | 빛 |
| :--- | :--- | :--- |
| **① 과제 완료 전** | T-1 ~ T-8 (판독 15장 끝날 때까지) | **어두운 사무실.** 광원은 셋뿐: 천장 **형광등 하나**(가끔 깜빡임 — T-7 "형광등이 하나밖에 안 들어와서요") · 컴퓨터 · CRT 화면의 **녹색** · 창밖 빗속 **렉스코드 간판 시안**. 실내 바탕은 따뜻한 그늘 계열을 한 단계 어둡게, 호박색 광원 없음 |
| **② 스탠드 설치** | T-8 끝 「あかるい!」 | 주임 책상에 **노란(호박) 불빛**이 켜지고, 실내 밝기 층이 0.6초에 걸쳐 따뜻하게 올라감 — Day 1의 시각적 보상 |
| **③ 이후** | T-9 퇴근(밤) ~ 다음 날 | 스탠드 호박 + 형광등 + CRT 녹색. 밤엔 창밖 시안 간판이 더 진함 |
| **④ 햇빛 · 먼지** | B4 '비가 그친다' 이후, 진행 연동 하늘이 갠 날 (D-11) | 창으로 **햇빛 기둥 + 먼지** — 晴れる의 보상. 그 전엔 창으로 해가 들지 않음 |

- 먼지 입자는 ②부터 스탠드 불빛 안에만 조금 (①에는 없음 — 어둠 속에선 보이지 않음).
- 구현: 단면 그림은 **한 장**, 밝기는 '실내 밝기 층'(곱하기 + 더하기 조명 층)과 광원별 빛 웅덩이로 코드에서 바꿈 → 전/후 그림을 두 번 그리지 않음 ([SLICE_ASSETS](SLICE_ASSETS.md) §2).

> **확정 A-1** (2026-11-03, 소유자 수정) — Day 1은 비. **스탠드 전에는 화면 빛(녹색) · 형광등 하나 · 창밖 간판 빛뿐인 어두운 사무실, 과제를 끝내 스탠드가 켜지면 따뜻하게 밝아짐.** 햇빛 · 먼지는 B4 '갬' 이후의 보상.

## 4. 시점 · 구도

- **2.5D 측면 단면** (건물을 세로로 자른 단면: 위층 연구실 · 나선 계단 · 지하 「源」). 아이소메트릭이 아님 (v3 피드백 · 스파이크).
- 소품은 **3/4 윗면이 보이는 정면**: 윗면 3~6px (ART_BIBLE v2.2 '3/4 윗면'). 가구 앞면은 화면을 향함.
- 바닥선: 각 층 바닥은 수평. 층 두께(단면) 8px, 잘린 단면은 콘크리트 + 철근 점.
- 깊이 3층: 뒤(벽 · 창 · 선반, 살짝 어둡게) / 가운데(가구 · 사람) / 앞(전선 · 담쟁이, 크고 흐리게 — 패럴랙스 1.2배).

> **확정 A-2** (2026-11-03) — 단면 vs 아이소메트릭. **확정: 단면** (GAME_DESIGN §9.1 · ART_BIBLE §9의 아이소 규격은 Godot에서 쓰지 않음). 아이소 v2 그림 자산은 참고로만 남김.

## 5. 캐릭터

### 5.1 비율 · 크기

| 항목 | 값 |
| :--- | :--- |
| 머리 비율 | **약 3등신** (v1 스프라이트처럼). Pixellab v3의 사실적 비율 금지 |
| 단면 스프라이트 캔버스 | **68×68** 아트 픽셀 (오너가 Pixellab에 만든 캐릭터 그대로), 서 있는 키 **약 58px**, 머리(머리카락 포함) **약 26px**. 앉은 상태는 의자까지 한 그림 |
| 정렬 | 발끝 = 캔버스 아래 2px 위, 가로 가운데 |
| 방향 | **옆(좌) · 3/4 앞** 2방향, 오른쪽은 좌우 반전 |
| 외곽선 | 잉크 `#231620` 1px, 빛 받는 쪽 바깥선은 한 단계 밝은 색 (선택적 외곽선) |

| 확대 컷 | 초상의 얼굴 부분을 **정수배(×2)** 잘라 확대 — 새 그림 없음 |

> **확정 A-3** (2026-11-03) — 초상 크기. 예전 규격은 64×64. **확정: 96×96** (대사창 CRT 안에 들어가고, 주임의 표정 8종 차이가 보임). 64로 하면 제작은 빠르지만 `난감`(눈 반쯤 감고 입꼬리 경련) 같은 표정이 2~3픽셀 차이로 줄어듦.

### 5.1-1 앉기 · 가구 분리

- 앉은 인물은 책상 **앞**에 그린다 (배경 → 인물, 책상 앞 층 없음 — 2026-11-04 오너 확정). 의자는 앉은 캐릭터 그림에 함께 들어 있다.
- 책상 상판 높이 = 바닥 위 **25px** (68px 캐릭터 기준, 2026-11-04 37px에서 낮춤). 앉는 방향은 그 자리 컴퓨터 화면 방향에 맞춘다 (화면이 정면이면 뒷모습, 옆이면 옆모습). 자리 값은 [SLICE_ASSETS §1-2](SLICE_ASSETS.md).

> **확정 A-4** (2026-11-03) — 픽셀 글꼴을 쓸지. **확정: 판독 문서(종이)는 매끈한 명조**(종이에 인쇄된 글자 — 스파이크의 히라기노 명조가 잘 어울렸음), **대사 · UI는 픽셀 고딕**(한글 · 가나 · 상용한자를 다 지원하는 무료 글꼴 후보를 P2 초반에 확인). 글꼴 라이선스는 소유자 확인.

## 9. 폰 대비 규칙 (로드맵 D1 보강)

데스크톱(macOS)이 먼저지만, 나중에 **폰 가로 모드**로 그대로 낼 수 있게 슬라이스부터 지킨다 (소유자 확정 2026-11-03).

| 규칙 | 기준 (1280×720 화면 기준 · 아트 픽셀) |
| :--- | :--- |
| **마우스 오버 전용 기능 금지** | 올려야만 보이는 정보 · 동작 없음. 뜻 보기 · 쪽지 · 설명은 전부 **누르기**로. 오버는 강조 표시(빛남) 같은 보조로만 |
| **누르는 영역 최소 크기** | **64×64 화면 px (= 32×32 아트 px)** 이상 — 폰 가로(약 844pt 폭)로 줄였을 때 약 44pt. 그림이 작으면 투명한 누름 영역을 넓힘. 누름 영역끼리 8px 이상 띄움 |
| **키보드 단축키는 보조** | 모든 조작은 누르기 / 클릭으로 가능해야 함. 단축키(Space · 1~4 · Esc · Tab · R)는 추가 수단. 드래그가 필요한 조작(손잡이)도 한 번 누르기로 됨 |
| **글자 최소 크기** | 대사 · 판독 본문 **24px** 이상, 보조 글자(후리가나 · 라벨 · 시스템 안내) **16px** 이상 (폰에서 약 16pt · 10.5pt). 글자 크기 옵션 '크게'는 ×1.25 |
| **화면 방향** | **가로 16:9 고정.** 세로 모드는 만들지 않음 |
| 길게 누르기 | 장면 건너뛰기(Esc 길게)는 화면의 '건너뛰기' 버튼 길게 누르기로도 |

- 이 규칙은 MOCKUPS 모든 시안의 확인 항목이고, P2 완료 기준(키보드만으로 완주)과 함께 **마우스/터치만으로 완주**도 확인한다.
