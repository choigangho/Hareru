# Hareru 게임 챕터 기획서 (가제: 「漢字復興計画」 한자 부흥 계획)

> 상태: **기획 초안 v0.1** (2026-11-01) — 사용자 아이디어를 정리하고 시스템으로 확장한 문서. 확정되지 않은 결정은 §10에 모음.
> 장르: 경영 시뮬레이션 (카이로소프트류의 '작은 시설을 키우는 재미'). 아트는 **픽셀 아트** (2026-11-01 결정, §9.1 원칙 참고).

---

## 1. 한 줄 요약

**잊혀진 한자를 되살리는 마지막 연구소를, 나의 실제 일본어 학습으로 키워 나가는 경영 시뮬레이션.**
카드 학습(학습 탭)이 곧 연구 성과가 되고, 연구 성과로 작은 사무실이 국가 기관으로 커지며, JLPT N1 합격이 진엔딩.

## 2. 세계관

- **시대**: 2XXX년 일본. 뉴럴링크가 보편화되어 사람들은 전용 저급 언어로 '텔레파시' 대화를 함.
- **쇠퇴의 흐름**: 전통 언어 사용 감소 → 어려운 한자부터 사라짐 → 결국 한자 자체가 잊혀짐.
- **무대**: **国立言語遺産研究所 (국립언어유산연구소, NJL)** — 가상 기관. 영향력이 줄어 국가 지원은 최소, 연구는 로봇(하드웨어)과 AI(소프트웨어)가 하지만 **법적으로 사람 1명은 상주해야 함** → 그 1명이 가이드 연구원.
- **분위기**: 시작은 '흐림'. 연구소가 성장할수록 연구소 위 하늘이 갬 → 앱 이름 **晴れる**와 직결.
  - 앱의 실제 날씨 엔진과 별개로, 게임 안 연구소 하늘은 **연구소 영향력**으로 정해지는 '연구소 날씨'를 가짐 (흐림 → 갬 → 쾌청).

## 3. 핵심 루프

```
[학습 탭] 카드 학습 (FSRS)
    │  외운 단어 · 복습 · 반응 시간 기록
    ▼
[연구 성과 정산]  연구 포인트 · 복원 진척 · 인물별 호감도
    │
    ▼
[게임 탭] 연구소 경영
    │  시설 건설/배치 · 로봇/AI 모듈 업그레이드 · 복원 프로젝트 · 이벤트
    ▼
[연구소 영향력 ↑] → 국가 예산 ↑ → 더 큰 시설 → 더 많은 단어 해금 동기
    │
    └──→ 다시 학습 탭으로 (오늘의 복습·새 단어)
```

**원칙: 게임 안에서는 '자원을 쓰는 결정'을 하고, 자원을 '버는 행위'는 실제 학습이다.**
게임 플레이만 반복해서 자원을 무한히 벌 수 없도록 설계 (공부를 대체하지 않고 공부를 이끌게).

## 4. 자원 · 경제

| 자원 | 얻는 법 | 쓰는 곳 |
| :--- | :--- | :--- |
| **研究P (연구 포인트)** | 학습 탭에서 단어 암기 완료(4등급 이상), 복습 예정 카드 복습, 연속 학습일. FSRS 기준으로 **오래 기억할수록(안정도 S 증가) 더 많이** 지급 | 복원 프로젝트, 시설 연구 |
| **予算 (국가 예산)** | 분기마다 '연구소 영향력'에 비례해 지급 | 시설 건설, 로봇·AI 모듈 구입, 이벤트 |
| **影響力 (영향력)** | 한자 복원, 인물 영입, 연간 평가 이벤트 성과 | 예산 증가, 연구소 날씨 개선, 시설 단계 해금 |
| **호감도** (인물별) | 그 인물이 음성을 맡은 단어의 숙련도 = 호감도 | 인물 에피소드·특수 시설 해금 |

### 4.1 학습 → 보상 변환 (과학적 무결성 규칙)

1. **보상의 근거는 `ReviewLogEntry`와 `WordMemorySnapshot`뿐** — 게임은 기록을 '읽기만' 하고 수정하지 않음.
2. **같은 날 같은 단어 중복 보상 금지** — FSRS 하루 8회 상한과 같은 철학. 반복 클릭 파밍 차단.
3. **보상 크기 = 기억 품질**: 단순 횟수가 아니라 안정도(S) 증가분, 복습 예정일을 지킨 복습에 가중치. '쉬움' 남발은 반응 시간 히든 등급이 자동 보정.
4. **게임 안 문제(미니게임)는 복습 예정(due) 카드만** FSRS에 반영하고, 반응 시간 기준도 카드 학습과 동일. 그 외 게임 문제는 연출용(FSRS 미반영).
5. **쉬는 날 패널티 최소화**: 연구소가 망가지지는 않음. 연구원이 걱정하는 대사, 연구소 날씨가 살짝 흐려지는 정도 (죄책감이 아닌 그리움).

## 5. 경영 시스템 (카이로소프트급 볼륨을 위한 축)

### 5.1 연구소 성장 단계 (= 급수 챕터)

| 단계 | 공간 | 급수 연동 | 연구소 날씨 |
| :---: | :--- | :--- | :--- |
| 1 | 낡은 사무실 한 칸 (책상 하나, 고장 난 로봇) | N5 | 흐림 · 비 |
| 2 | 사무실 층 전체 | N4 | 흐림 |
| 3 | 연구동 건물 | N3 | 구름 조금 |
| 4 | 연구 캠퍼스 (서고 · 녹음 스튜디오 · 강의동) | N2 | 맑음 |
| 5 | 국가 언어 재건 본부 | N1 | 쾌청 → **晴れる 진엔딩** |

단계 승급 조건 = 해당 급수 단어 일정 비율 암기 + 영향력 + **승급 심사 이벤트(그 급수 모의고사)**.

### 5.2 시설 (방 단위 배치 · 인접 콤보)

- 시설을 격자에 배치하고, **특정 조합을 붙여 놓으면 콤보 보너스** (카이로소프트식 배치 퍼즐 재미).
- 예시 (최종 60종 이상 목표):
  - **한자 서고**: 복원된 한자 보관. 서고 수 = 동시 진행 가능한 복원 프로젝트 수
  - **녹음 부스**: 인물의 음성 수집 → 그 인물이 맡은 단어 음성 해금 연출
  - **필사실**: 획순·부수 연구 (한자 상세 정보 해금)
  - **휴게실 · 자판기**: 연구원 기분 ↑ (가이드 대사 변화)
  - **서버실**: AI 모듈 슬롯
  - 콤보 예: `서고 + 필사실 + 연구원 책상` = 「写本工房」 연구 속도 +20%

### 5.3 로봇 · AI 모듈 (카이로소프트의 '직원' 역할)

- 사람은 연구원 1명뿐이라는 설정 → 직원 대신 **로봇 하드웨어 + AI 소프트웨어 모듈**을 영입·업그레이드.
- 모듈 예: 「音読AI」(음독 분석), 「訓読AI」, 「部首解析ロボ」, 「語源調査ドローン」…
- 모듈 레벨업 재료 = 연구P. 모듈 조합에 따라 복원 프로젝트 효율이 달라짐.

### 5.4 한자 복원 프로젝트 (메인 컬렉션)

- **잊혀진 한자 하나하나가 복원 대상.** 상용한자 2,136자 전체를 장기 컬렉션 목표로.
- 복원 조건: 그 한자가 들어간 단어를 N개 암기 (실제 학습 데이터 기반) + 연구P 투자.
- 복원하면:
  - 연구소 창밖 도시 풍경에 **그 한자가 쓰인 간판·표지판이 되살아남** (시각적 성취감)
  - 연구원의 해설 대사 (마니아 텐션)
  - 한자 도감에 등록 (음훈·부수·관련 단어)

### 5.5 연간 캘린더 & 이벤트

## 6. 가이드 연구원 시스템

- 카이로소프트의 비서처럼 **모든 시스템의 첫 안내와 피드백**을 담당.
- 학습 탭과의 연결: 학습 카드 상단의 안내 문구(보류 1번)를 이 연구원의 짧은 코멘트로 대체할 수 있음.
  - 예: 어려운 단어를 '알고있음'으로 넘기면 「えっ、それ知ってるんですか!? さすが…」
- 연구원 상태: 기분/피로도, 연구소 단계에 따른 의상·책상 변화, 호감도에 따른 개인 에피소드.
- 진엔딩: N1 달성 → 연구원이 '최후의 1인'이 아니게 됨 (주인공이 두 번째 계승자) → 연구소 위 완전한 晴れ.

### 6.1 이름 — 「글자는 알아도 읽을 수 없는 이름」 (엔딩에서 공개)

> 🕓 **방향 확정, 세부는 추후 결정** (2026-11-01): 아래는 현재 합의된 방향. 정확한 이름과 연출 디테일은 나중에 확정.

**설정 — 名乗り(나노리) 읽기**: 일본 이름에는 이름에만 쓰는 비표준 읽기(名乗り)가 많아서, 실제 일본인끼리도 「お名前、何とお読みするんですか?」 하고 읽는 법을 묻는 문화가 있음.
연구원의 이름도 **한자 자체는 배우면 알 수 있지만, 이름으로 읽는 법은 표준과 달라** 엔딩까지 아무도 모름.

**연출 흐름**
1. **한자는 학습으로 선명해짐**: 이름의 각 한자는 처음엔 블러 처리. 그 한자가 들어간 단어를 학습 탭에서 외우면 **그 글자만 선명해짐** (카드 앞면 예문 블러와 같은 시각 언어).
   → 엔딩 훨씬 전에 플레이어는 이름의 '글자'는 다 알게 됨.
2. **읽는 법은 끝까지 모름**: 이름표의 후리가나 자리는 항상 「？？？」. 플레이어가 아는 음독·훈독으로 읽어 보는 이벤트가 있어도 연구원은 웃으며 "땡, 그렇게 안 읽어요".
3. **검색해도 모름**: 연구소 단말·AI 모듈에 읽는 법을 물어도 「該当データなし」 — 이름 읽기(名乗り) 데이터는 소실됨.
4. **엔딩에서 공개**: 실제 JLPT N1 합격 신고 → 연구원이 처음으로 자기 이름을 소리 내어 읽어 주고 후리가나가 채워짐 (가능하면 음성으로). 이름의 뜻을 직접 설명.

**공개될 이름 후보** (최종 선택 대기 — 뜻이 엔딩 메시지와 이어지도록)

| 후보 | 읽기 | 뜻 · 엔딩과의 연결 |
| :--- | :--- | :--- |
| **言継 晴** (추천) | ことつぐ はる | 言(말)을 継(잇다) + 晴(갬). '말을 이어 하늘을 개게 하는 사람' → 앱 이름 晴れる와 엔딩의 맑은 하늘이 그녀의 이름이었다는 반전 |
| 灯守 詞 | ひもり ことば | 灯守(등불지기) + 詞(말). '꺼져 가는 말의 등불을 지키는 사람' → 최후의 1인 설정과 직결 |
| 篠宮 綴 | しのみや つづり | 綴る = 글자를 엮어 쓰다. '글자를 잇는 사람' → 차분하고 문학적인 톤 |

- 이름은 코드에 직접 쓰지 않고 게임 문자열 데이터 한 곳에서만 관리 (스포일러 방지 + 교체 용이).

### 6.2 대사 언어 비율 — 한국어 80 · 일본어 20 (결정)

- **한국어 80%**: 스토리·시스템 안내·튜토리얼 등 이해가 꼭 필요한 문장.
- **일본어 20%**: 연구원의 감탄사·입버릇(「なるほど!」「さすがです!」), 인사, 그리고 **플레이어가 이미 외운 단어**가 들어간 짧은 대사.
- 원칙: 일본어 대사는 가능한 한 학습 데이터와 연결 — 아직 안 배운 어려운 단어는 쓰지 않고, 외운 단어는 일본어로 등장시켜 '알아듣는 기쁨'을 줌.
- 일본어 대사에는 기본적으로 후리가나·한국어 보조 해석을 탭하면 볼 수 있게.

## 7. 엔딩 · 클리어 조건

- **진엔딩**: 실제 JLPT N1 합격을 **자기 신고**하면 진엔딩 (2026-11-01 결정).
- **신고 화면 흐름**:
  1. 응시 회차(7월/12월) · 급수 선택 → 앱이 알고 있는 공식 시험일과 대조
  2. 척도 점수 입력 (종합 + 영역별) → 앱이 **합격 기준을 자동 확인**
     - N1: 종합 100/180 이상 + 영역별(언어지식 · 독해 · 청해) 각 19/60 이상
     - (N2 90 · N3 95 · N4 90 · N5 80 이상 등 급수별 기준 — 출시 전 JLPT 공식 기준 재확인 필요)
  3. 선택: 합격 결과 화면 사진 첨부 (앱 안에만 보관, 외부 전송 없음)
  4. 연구원의 축하 연출 → 진엔딩
- **결과 발표 시기**: 실제 합격 발표는 시험 약 2개월 뒤라서, 시험 직후~발표 전에는 연구원이 결과를 기다리는 '대기 이벤트'를 둠.
- **신뢰 문제**: 자기 신고라 검증할 수 없음 → 엔딩은 개인적 성취를 축하하는 용도로만 쓰고, 랭킹·보상 경쟁 요소와는 연결하지 않음.
- N4·N3·N2 합격 신고도 받아서 **특별 이벤트·칭호**로 축하 (진엔딩은 N1만).
- 연구소 단계 승급(§5.1)은 기존대로 앱 안 학습 진도 + 모의고사로 진행 — 실제 시험 전에도 게임이 계속 진행되도록.

## 9. 기술 설계 방향 (이 코드베이스 기준)

- **렌더링**: 연구소 디오라마는 `SpriteKit`(다수 오브젝트·애니메이션·탭 판정)을 `SpriteView`로 SwiftUI에 임베드. UI 패널은 기존 Liquid Glass 컴포넌트 재사용.
- **데이터 주도**: 시설·모듈·콤보·이벤트·대사를 전부 JSON(`Resources/Data/game/*.json`)으로 → 코드 수정 없이 콘텐츠 확장 (카이로소프트급 볼륨의 전제).
- **상태 저장**: 기존 SwiftData 스토어에 `InstituteState`(단계, 배치, 자원, 진행 이벤트) 추가. 학습 기록과 **별도 모델**로 두어 게임 버그가 학습 데이터를 망가뜨리지 않게 격리.
- **보상 정산기**: `ResearchRewardCalculator` — `ReviewLogEntry`/스냅샷 → 연구P 계산 순수 함수 + 단위 테스트 (FSRS 무결성 규칙 §4.1을 테스트로 고정).
- **재활용**: 레거시 `SMSEpisodeEngine`(문자 대화 연출) → 인물/연구원 대화 연출 엔진으로 개조.
- **아트 파이프라인**: 픽셀 아트 (§9.1). SpriteKit 텍스처는 `filteringMode = .nearest`, 화면 배율은 정수배로만 확대해 픽셀이 뭉개지지 않게.

### 9.1 픽셀 아트 원칙 (2026-11-01 결정)

- **카이로소프트를 그대로 따라 한 느낌 금지**: 장르 재미(작은 시설 키우기)만 가져오고, 캐릭터 비율·UI 틀·색감은 Hareru만의 것으로.
- **앱 전체 톤과 연결**: 게임 화면 안은 픽셀, 바깥 패널(자원·메뉴)은 기존 Liquid Glass UI → '유리창 너머로 들여다보는 픽셀 연구소' 콘셉트.
- **날씨·시간대 연동**: 픽셀 에셋은 한 벌만 만들고, 앱의 실제 날씨·시간대 팔레트(`WeatherSkyPalette`)로 색 보정·조명 레이어를 코드로 입힘 → 에셋 수 절약 + 앱의 '고급 날씨' 정체성 유지.
- **시점: 아이소메트릭 픽셀** (2026-11-01 결정) — 2:1 아이소메트릭 격자(타일 너비:높이 = 2:1). 방을 비스듬히 내려다보는 디오라마형 연구소.
  - 시설 배치 격자·인접 콤보 판정은 아이소메트릭 좌표(행·열) 기준으로, 화면 좌표 변환은 한 곳(`IsoGrid`)에서만.
  - 오브젝트 앞뒤 가림은 행+열 합으로 깊이 정렬 (SpriteKit `zPosition`).
  - 회전은 4방향 고정이 아닌 **1방향 고정**으로 시작 (에셋 수 1/4) — 필요하면 나중에 확장.
- **해상도 가이드**: 바닥 타일 32×16(아이소메트릭 2:1), 캐릭터 32×32 기준, 연구원 대화 초상화는 64×64 이상의 고해상도 픽셀.
- **장점**: 일러스트 대비 제작 비용이 낮아 '카이로소프트급 볼륨'(시설 60종 이상)을 현실적으로 만들 수 있음.
