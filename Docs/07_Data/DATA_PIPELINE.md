## 3. 처리 단계

원본 파일은 `Tools/sources/`(git 제외)에 두고, 스크립트는 `Tools/`에 둠. 원본은 다운로드한 데이터일 뿐이므로 실행하지 않고 파싱만 함.

1. **한자 빌드** (`build_kanji.py`)
   - KANJIDIC2에서 상용한자 2,136자 추출: 음독·훈독·획수·부수·영어 뜻·옛 JLPT 급수.
   - 새 JLPT 급수(N5~N1)는 그 한자가 처음 등장하는 단어의 급수로 재추정.
2. **단어 빌드** (`build_words.py`)
   - JLPT 목록 × JMdict 매칭 → 표기·읽기·품사·영어 뜻(뜻 2~4개로 압축).
   - JmdictFurigana로 `kanjiUsages`(한자별 실제 발음) 자동 생성 → 표제어 루비가 한자 위에 정확히 붙음.
   - 동음이의·표기 흔들림은 매칭 실패 목록으로 따로 뽑아 검수.
3. **한국어 초안** (AI 초안 + 검수)
   - 한자: 훈음(예: 달 감)·한국어 뜻.
   - 단어: 한국어 뜻·품사.
   - 각 항목에 `reviewStatus: "draft" | "reviewed"` 표시 → 급수별로 검수.
4. **예문 초안** (AI 초안 + 검수)
   - 뜻마다 예문 1개: `{漢字|かんじ}` 후리가나 마크업 + `before / answer / after` 3분할 해석 (음성 캐릭터 배정은 게임 인물 확정 후).
   - 기존 `CatalogRepository.validationIssues()` 무결성 검사를 통과해야만 앱 데이터로 내보냄.
5. **앱 데이터 내보내기**: 급수별 파일 분리(`words_n5.json` …)로 앱 시작 시 로딩 부담 분산.

**N5에서 남은 것**
- `ラジオカセ` 1개: 목록 표기 오류(바른 말 ラジカセ) — 초안 보류, 검수 때 표기 정정 또는 제외 결정.
- 음성 캐릭터는 **게임 인물과 연동하기로 결정**되어, 초안의 캐릭터 배정을 모두 '미정'(`unassigned`)으로 되돌림. 인물이 확정되면 다시 배정.
- 예문 일부는 기존 성우 라인업(기사단장·연금술 상인·탐정·탐험대장 등)의 말투와 소재(剣, 騎士, 薬草, 犯人 …)로 쓰여 있음 → 게임 인물이 정해지면 그 세계관에 맞게 다시 쓸지 검수 때 결정.
- 상용한자 밖 한자 151자도 한자 데이터에 포함하도록 `build_kanji.py`를 확장 (飴·醤油·石鹸 등).

**검수가 필요한 항목** (`issues` 필드로 표시)
- `jmdict_unmatched` 32개: 인사말·관용 표현(お元気で, 行っていらっしゃい 등)과 목록 표기 오류(ラジオカセ 등).
- `reading_adjusted` 25개: 목록의 읽기가 표기와 달라 JMdict 대표 읽기로 보정. 일부는 잘못 보정됐을 수 있음 (예: 適 → たまたま).
- `kanji_usage_estimated` 35개: 当て字·숙자훈(可愛い, 真っ赤)이라 한자별 읽기 데이터가 없어 묶음 읽기로 추정.
- 상용한자 밖 한자를 포함한 단어 198개 (`nonJoyoKanji`): 한자 상세 정보가 없으므로 앱에서 한자 터치를 막거나 한자 데이터를 추가해야 함.

**급수 추정 방식 (한자)**: KANJIDIC2의 옛 4단계 급수를 기준으로, 옛 2급은 (처음 등장하는 단어 급수, 사용 빈도) 순으로 앞 370자 N3 · 나머지 N2.

## 3.2 한국어 뜻 · 예문 작성 규칙 (N5 시험 배치 20단어로 확정, 2026-11-01)

- **뜻**: 짧게 1~2개 (예: '어른, 성인'). 다의어는 자주 쓰는 뜻 최대 2~3개만 별도 sense로.
- **품사**: 한국어 표기 — 동사 / い형용사 / な형용사 / 명사 / 부사 / 대명사 등.
- **대분류** (`category`, 2026-11-02 확정 · `Docs/Archive/TOWN_DRAFT.md`): 생활 · 교육 · 사회 · 교통·이동 · 사물·형태 · 경제 · 업무 · 정치·행정 · 학술 · 추상·논리 · 미디어 · 분야 없음 (11개 + 분야 없음, 교통·이동 · 사물·형태는 같은 날 추가) — 단어마다 하나, 급수와 상관없이 같은 기준. 대분류가 담당 인물을 정함. 학교 단어는 반드시 교육, 음식·식기는 생활, 시간·숫자 명사(날짜·요일·시각·수·조수사)는 업무(KURO).
  - 분야 없음이면 `fieldlessVoice`: `protagonist`(감탄사·인사·기초 동작) / `chiefResearcher`(접속사·부사·사고·판단·지시어·색). 초안 짧은 형식은 `"f": "P"/"C"`.
  - `aboveLevelKanji: true`: 단어 급수보다 어려운 (추정) 급수의 한자 포함 — 담당 인물을 만나기 전까지 주인공 음성. 내보낼 때 자동 계산.
- **급수별 표기** (2026-11-02, JLPT 출제 방식): 그 급수까지의 한자만 한자로, 아직 안 배운 한자는 히라가나로 (예: N5 `べんきょう` → N4 `勉強`, `しょうゆ` → N3 `しょう油` → N1 `醤油`). 내보낼 때 자동 생성, 표기가 바뀌는 단어만.
  - 단어 `notations`: `[{"level", "term"}]` — 단어 급수부터 표기가 바뀌는 지점마다. 마지막이 원래 표제어.
  - 뜻 `exampleNotations`: `[{"level", "markup"}]` — 예문의 `{漢字|かな}` 묶음 중 그 급수보다 어려운 한자가 든 묶음은 가나로.
  - 뜻 `exampleTarget`: `[앞, 표적 단어, 뒤]` 예문 마크업 조각 (번역의 before/answer/after와 같은 모양, 이으면 원래 마크업). 활용형까지 포함 (`{疲|つか}れた`), 조수사는 수와 묶인 묶음 전체(`{五百円|ごひゃくえん}`). `exampleNotations` 항목마다 같은 모양의 `target`.
  - 뜻 `voiceTone`(선택): 예문 음성의 반전 톤 (`fast` 등). 없으면 인물 기본 톤. 초안 짧은 형식 `s`의 8번째 칸.
  - 단어 `trauma`(선택): `"mid"` | `"low"` — 판독 후 심리 연출 · 1~2일차 대기열 제외용 (FSRS 무관). 원본 목록은 `Docs/03_Story/Acts/N5/N5_SCRIPT.md` §4.1, 초안 단어 항목의 `"trauma"` 키로 옮겨 둠.
  - 예문 표기 = 카드 단어 표기와 같은 한자 급수 판정 → 같은 급수에서 항상 함께 바뀜. 읽기는 묶음의 가나를 이어 붙이면 되므로 음성 입력(가나)도 여기서 나옴 — 형태소 분석 불필요.
  - 상용한자 밖 한자는 N1 취급, 当て字·숙자훈(可愛い 등)은 한 글자씩 못 바꾸므로 단어 전체를 가나로.
  - 앱(예정): 사용자의 현재 급수에 맞는 표기를 앞면에 보여 주고, 표기가 한자로 바뀌는 순간 같은 카드를 FSRS 재학습 상태로 (실패 횟수에는 넣지 않음).
  - 한자 급수는 추정값(공식 목록 없음) — 이 추정이 '언제 한자로 바뀌는가'를 정함.
  - 기준 목록은 `Tools/draft_korean.py`의 `DOMAINS`. 옛 카테고리가 남은 초안은 `--reclassify`로 바꿈 (N5·N4는 2026-11-02 손으로 분류 완료).
- **예문**
  - 말투·소재는 중립적으로 (음성 캐릭터 미정). 게임 인물이 정해지면 그 인물의 말투로 다듬을 수 있게.
  - **단어 급수보다 어려운 한자도 허용** (자연스러운 문장 우선). 대신 뒷면에서 모든 한자에 후리가나가 붙도록 예문의 한자는 전부 `{漢字|かな}` 마크업.
  - 한 문장, 너무 길지 않게 (카드 한 화면 안).
- **3분할 해석**: `answer`는 표제어에 해당하는 한국어 부분만, 앞뒤는 `before`/`after`. 어순상 앞이 비면 `before`는 빈 문자열.
- **가나만 쓰는 단어**: `nonKanjiNote` 필수 — 외래어는 원어, 고유어는 보통 가나로 쓰는 이유·한자 표기.
- **음성 캐릭터 배정**: 게임 음성 캐릭터 10인(`Docs/Archive/GAME_DESIGN.md` §2.2, `VoiceProfile.gameCast`)의 담당 어휘 영역에 맞춰 배정. 단, 예문 재작성은 게임 설계 후(§4) — 그 전 초안은 `voiceId` null.
- **검사**: `export_catalog.py` → `swift test` (`testPilotCatalogExportPassesAppValidation`) 통과해야 앱 반영.

## 4. 진행 순서 (2026-11-01 변경: 게임 먼저, 예문은 그다음)

예문을 게임 인물·장면과 연결하려면 게임이 먼저 있어야 하므로 순서를 바꿈.

1. **지금 유지하는 것** (게임과 무관하게 그대로 사용)
   - 한자 기본 데이터 + N5 한자 447자 한국어 훈음·뜻 초안
   - 단어 기본 데이터(7,986개) + N5 단어 712개 한국어 뜻·품사 초안
2. **보류 — 게임 먼저**: 연구소 게임의 인물(주연·조연·기타 인물)·장면·말투를 설계 (`Docs/Archive/GAME_DESIGN.md`).
3. **그다음 예문**: 게임 인물·장면에 맞춰 예문을 구상하고 음성 캐릭터를 배정.
   - **N5 예문 715개 확정 (2026-11-03)**: N5 스토리(`Docs/03_Story/Acts/N5/lines/`) 완성 후 전부 다시 씀. 뜻마다 담당 인물(대분류 → `voiceId`, 분야 없음은 `protagonist`/`guide_researcher`)의 말투로, 줄거리 핵심은 넣지 않음. 앱 번들의 옛 견본 31단어는 그대로(옛 voiceId).
   - **순서 (2026-11-02 합의)**: 그 급수 스토리(대사 포함) 완성 → 예문 확정 → 음성 합성. N4부터는 다음 급수 스토리를 쓰는 동안 이전 급수 예문·음성 진행. 확정되면 음성 세션에 알림.
   - 예문 = 그 세계의 한 장면, 단어 담당 인물(대분류)의 말투로. 줄거리 핵심(반전·정체·사건 결과)은 넣지 않음 — 학습 순서가 사용자마다 다르므로.
4. N4~N1 한국어 뜻은 게임과 무관하므로 필요하면 먼저 진행 가능. 예문은 3번 이후.
5. 음성은 예문이 확정된 뒤 `synthesize_aivis.py`로 일괄 처리.
