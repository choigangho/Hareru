# Hareru (晴れる) — 보류 작업 목록

> 사용자 요청으로 **지금은 손대지 않고 보류**한 항목들입니다. 착수할 때 이 문서에서 지우고 커밋 메시지에 남겨 주세요.
> 최종 정리: 2026-11-01

## 앱이 가장 중요하게 여기는 축 (모든 보류 항목의 판단 기준)

1. 암기 관련 과학적 알고리즘 (FSRS + 반응 시간 기반 히든 등급)
2. 고급스러운 실시간 현재 위치 날씨 · 시간대 반영 애니메이션
3. 색상 — 컬러 조합 이론에 근거한 배색
4. 방대한 단어별 음성 데이터(캐릭터 성우)와 예문 데이터
5. 단어 · 통계 · 날씨 · 캐릭터가 유기적으로 엮인 최종 종합 게임 (챕터 이름 미정)
6. JLPT 목표와 통계 데이터 시각화

## 보류 항목

### 1. 학습 카드 상단 안내 문구 정리
- **현재**: 평가 후 "잠시 후 한 번 더 만나요", "N일 뒤 다시 만나요" 같은 배너가 카드 위에 뜸.
- **방향**: 정말 필요한 안내만 남김. 게임 챕터가 구현되면 안내 문구의 약 80%가 게임 챕터와 이어질 예정이라, 게임 설계 후 함께 정리.
- **위치**: `WordDeckView.handleEvaluation(button:)`, 배너 슬롯은 높이 30pt로 고정되어 있어 문구 유무와 관계없이 카드·버튼 위치가 흔들리지 않음.

### 2. 실제 기상 데이터 연동 (WeatherKit 등)
- **현재**: 날씨 배경 · 애니메이션 고퀄리티화는 완료(2026-11-01, 22종 날씨 · OKLCH 배색). 다만 날씨 값은 여전히 위경도·날짜 시드 기반 **추정치**(`WeatherAtmosphereEngine.estimatedWeather`)이며 실제 기상 API와 연결되어 있지 않음 (계절별 후보 · 유성우 극대일 · 고위도 오로라만 반영).
- **할 일**: WeatherKit(또는 기상청 API) 응답을 `WeatherCondition` 22종으로 매핑, 실제 기온 표시, 호출 빈도 · 오프라인 대비 캐시. Apple 개발자 계정의 WeatherKit 권한 필요.
- **확인할 것** (몰아서 테스트 시): 시뮬레이터에서 22종 × 5시간대 렌더링, '동작 줄이기'에서 번개 섬광이 꺼지고 움직임이 느려지는지, 비 · 눈 장면 프레임 유지(60fps) 여부.

### 3. 카테고리별 아이덴티티 카드 색상
- **방향**: 단어마다 카테고리를 두고 카테고리별 고유 카드 색을 주되, 날씨에 따라 크게 바뀌는 UI와 어울려야 함.
- **현재**: `CategoryThemeGroup` 팔레트는 남아 있지만 학습 화면 배경이 날씨 하늘로 바뀌면서 화면에 쓰이지 않음.
- **아이디어**: OKLCH 색공간(`RGBAColor.oklch`)에서 카테고리마다 색상각만 고정하고, 명도·채도는 현재 하늘 팔레트에서 파생 → 어떤 날씨에서도 조화.

### 3-1. 음성을 맡는 게임 인물 설계
- **결정**: 단어·예문 음성은 연구소 게임의 인물(주연·조연·기타 인물)이 맡음. 기존 성우 라인업 10명(부장님·교토 할머니 등)은 쓰지 않음.
- **현재**: 새 데이터의 음성은 모두 '미정'(`VoiceProfile.unassigned`) → 카드에 별명 태그가 뜨지 않음. 기존 10명은 이미 번들된 30단어·녹음 오디오가 참조해서 코드에만 남아 있음 (인물이 정해지면 교체 후 삭제).
- **진행**: 인물 10인 라인업 확정 (2026-11-01, `GAME_DESIGN.md` §2.2, 코드 `VoiceProfile.gameCast`). 남은 일: 단어별 배정 → 예문 다시 쓰기 → 음성 합성 (모두 게임 설계 후).
- **순서 결정 (2026-11-01)**: 게임을 먼저 설계한 뒤 예문을 구상. 현재 N5 예문 715개는 임시.

### 4. 기념일 전용 배경 (크리스마스 · 추석 등)
- **방향**: 해당 날에는 날씨 배경 대신 컨셉에 맞는 개별 배경.
- **고려**: 추석은 음력 기준이라 연도별 날짜 계산(`Calendar(identifier: .chinese)`) 필요. 기간(당일만 vs 연휴 전체)과 날씨 시뮬레이터에서 미리보기 지원 여부 결정 필요.

### 5. 게임 챕터 「연구소」 (탭 순서: 학습 · 연구소 · 통계 · 설정, 게임 이름 미정)
- **기획서**: [`GAME_DESIGN.md`](GAME_DESIGN.md) — 2XXX년 国立言語遺産研究所(NJL) 경영 시뮬레이션 컨셉 (아래 초안 아이디어를 흡수·확장)
- **현재**: 탭과 임시 화면(`GameChapterPlaceholderView`)만 있음.
- **아이디어 초안** — 단어 · 통계 · 날씨 · 음성 캐릭터를 한 세계로 묶기:
  1. **하레루 동네 지도**: 음성 캐릭터(라멘집 사장님, 편의점 알바생, 교토 할머니…)가 각자 가게를 가진 동네. 그 캐릭터가 맡은 단어를 외울수록 가게가 열리고 대화 에피소드가 해금됨.
  2. **안개 걷기 = 복습**: 기억 유지율(FSRS R)이 떨어진 단어가 있는 구역은 안개로 덮임. 그 구역 손님 대화(복습 문제)를 풀면 안개가 걷히고 해가 듬 → 앱 이름 '晴れる'를 게임 규칙으로.
  3. **실제 날씨 연동 이벤트**: 비 오는 날엔 우산 가게·비 관련 어휘, 밤엔 이자카야 부장님만 영업처럼, 현재 위치 날씨·시간대에 따라 등장 캐릭터와 퀘스트가 바뀜.
  4. **인물 호감도**: 인물별 담당 단어의 숙련도가 곧 호감도. 레거시 SMS 게임(`Features/Game/`)의 문자 대화 형식을 캐릭터 스토리 연출로 재활용 가능.
  5. **통계 = 동네 성장**: 잔디 연속 일수는 축제, JLPT D-Day는 최종 '시험의 날' 이벤트(모의고사)로 연결.
  6. **듣기 중심 미니게임**: 캐릭터 목소리만 듣고 단어 고르기, 예문 빈칸 채우기 등 예문·음성 데이터를 그대로 활용.
- **알고리즘 원칙**: 게임 안 문제 풀이를 FSRS 기록으로 반영할 때는 '복습 예정(due)' 카드만, 카드 학습과 같은 반응 시간 기준으로 처리해 기억 데이터가 오염되지 않게 할 것. 그 외 게임 플레이는 FSRS에 반영하지 않음.
- **연결 예정**: 학습 카드 상단 안내 문구(보류 1번)의 약 80%가 이 챕터와 이어질 예정.

### 7. FSRS '알고있음' 6초 임계치 재검토
- 앞면 예문이 10초에 걸쳐 서서히 선명해지도록 바뀌었으므로(`CardTimingConfig.exampleFadeDuration`), 현재 기준은 다음과 같음:
  - 6초 안에 '정답 보기' → 표제어만으로 떠올린 것으로 보고 정상 등급
  - 6~10초 → 예문 문맥의 도움을 받은 것으로 보고 `hiddenHintAssisted`(재출제)
- 예문 페이드(10초)와 힌트 창(`hintWindowUpperBound` 10초)은 길이가 같도록 테스트로 묶여 있음.
- 실사용 피드백에 따라 `standardGoodUpperBound`를 7.5~8초로 올릴지 결정.

### 5-3. 인트로 · 온보딩 구현 (2026-11-02 사용자 구상)
- **기획**: [`GAME_DESIGN.md`](GAME_DESIGN.md) §12. 위치 반영 흑백 타이핑 인트로 → 이름 입력 → 가이드 튜토리얼 → 첫 학습 → 캐릭터 등장 → 시설 건설 → 보수 퀘스트.
- **먼저 정할 것**: 계정 가입 범위(서버 필요 여부), 위치 권한을 설정 단계에서 받는 시점, 진행 단계 저장 방식.

### 5-4. 1단계 초기 시설을 사용자 제공 방 그림으로 (2026-11-02)
- **쟁점**: 제공된 그림은 방 전체가 한 장. 현재 구조는 6×6 격자 + 시설 스프라이트 개별 배치.
- **제안**: 그림을 1단계의 **고정 배경 방**으로 쓰고, 그 위 바닥 영역만 격자로 열어 새 시설을 놓음. 안에 이미 있는 분재 · 연못 · 홀로그램 기둥 · 로봇 팔은 고정 장식, 책상은 연구원 자리와 맞춤. 더 깊게 하려면 요소별로 잘라 개별 스프라이트로 분리.
- **선행 작업**: 그림이 진짜 픽셀 격자가 아니라(AI 생성, 선 두께 불균일) 정수 배율 최근접 렌더에 맞게 **픽셀 정리(다운샘플 + 팔레트 고정)** 필요. 검은 배경은 투명 처리, 창 유리는 날씨가 비치도록 마스킹.
- **함께 정할 것**: 책상 2개(주임 · 신입)와 연구원 동선(길찾기 칸)을 그림의 바닥 구조에 어떻게 맞출지.

### 5-5. 음성 해금 = 캐릭터 만남 (2026-11-02 결정)
- 캐릭터를 만나기 전엔 그 캐릭터의 단어 음성이 잠김. 급수별 등장 캐릭터 기준으로 음성 배정(3-1과 연결). 구현 시 잠긴 음성 버튼 표시, 해금 연출, 저장 필드(`metCharacters`) 필요.

### 5-6. 픽셀 에셋 제작 도구: Pixellab (2026-11-02 검토)
- API(`https://api.pixellab.ai/v2`, Bearer 토큰): 아이소메트릭 타일, 4/8방향 캐릭터, 걷기 등 애니메이션, 타일셋, 맵 오브젝트. Claude용 MCP 서버와 Python/JS SDK 있음.
- 키는 저장소에 두지 않음(환경 변수 또는 MCP 설정). 기존 Higgsfield 산출물과 화풍이 맞는지 한 점 시험 생성 후 결정.

### 15. 창밖 도시 원근 층 분리 (2026-11-04)
- 단면 카메라가 거의 고정이라 지금은 층을 나눠도 티가 안 남 → 보류. 카메라 이동(패닝 · 확대)이 늘어나면 창 유리를 뚫고 하늘 · 먼 빌딩 · 중간 빌딩 · 가까운 빌딩+간판 층으로 다시 그림. 그때 간판 · 잉어 홀로그램 · 차 경로도 층에 맞춰 옮김. 지금 깊이감은 차 크기 · 속도 · 밝기 3단계와 비 속도 차이로만 냄 ([SLICE_ASSETS](Design/SLICE_ASSETS.md) §2).
