> 최종 정리: 2026-11-01

## 앱이 가장 중요하게 여기는 축 (모든 보류 항목의 판단 기준)

1. 암기 관련 과학적 알고리즘 (FSRS + 반응 시간 기반 히든 등급)
2. 고급스러운 실시간 현재 위치 날씨 · 시간대 반영 애니메이션
3. 색상 — 컬러 조합 이론에 근거한 배색
4. 방대한 단어별 음성 데이터(캐릭터 성우)와 예문 데이터
5. 단어 · 통계 · 날씨 · 캐릭터가 유기적으로 엮인 최종 종합 게임 (챕터 이름 미정)
6. JLPT 목표와 통계 데이터 시각화

## 보류 항목

### 1. 학습 카드 상단 안내 문구 정리
- **현재**: 평가 후 "잠시 후 한 번 더 만나요", "N일 뒤 다시 만나요" 같은 배너가 카드 위에 뜸.
- **방향**: 정말 필요한 안내만 남김. 게임 챕터가 구현되면 안내 문구의 약 80%가 게임 챕터와 이어질 예정이라, 게임 설계 후 함께 정리.
- **위치**: `WordDeckView.handleEvaluation(button:)`, 배너 슬롯은 높이 30pt로 고정되어 있어 문구 유무와 관계없이 카드·버튼 위치가 흔들리지 않음.

### 2. 날씨 배경 · 날씨 애니메이션 고퀄리티화
- **방향**: 더 높은 렌더링 품질과 더 세밀한 디테일 (빗방울 굴절, 구름 볼륨, 시간대별 빛 산란 등).
- **위치**: `WeatherSkyCanvasView.swift`, `WeatherAtmosphereEngine.swift`.
- **참고**: 현재 날씨는 위경도·날짜 시드 기반 **추정치**이며 실제 기상 API(WeatherKit 등)와 연결되어 있지 않음. 고퀄리티화와 함께 실데이터 연동 여부도 결정 필요.

### 3. 카테고리별 아이덴티티 카드 색상
- **방향**: 단어마다 카테고리를 두고 카테고리별 고유 카드 색을 주되, 날씨에 따라 크게 바뀌는 UI와 어울려야 함.
- **현재**: `CategoryThemeGroup` 팔레트는 남아 있지만 학습 화면 배경이 날씨 하늘로 바뀌면서 화면에 쓰이지 않음.
- **아이디어**: OKLCH 색공간(`RGBAColor.oklch`)에서 카테고리마다 색상각만 고정하고, 명도·채도는 현재 하늘 팔레트에서 파생 → 어떤 날씨에서도 조화.

### 4. 기념일 전용 배경 (크리스마스 · 추석 등)
- **방향**: 해당 날에는 날씨 배경 대신 컨셉에 맞는 개별 배경.
- **고려**: 추석은 음력 기준이라 연도별 날짜 계산(`Calendar(identifier: .chinese)`) 필요. 기간(당일만 vs 연휴 전체)과 날씨 시뮬레이터에서 미리보기 지원 여부 결정 필요.

## 인계 문서(`CLAUDE_CODE_HANDOVER.md`)에서 넘어온 미해결 항목

### 5. `words.json` N1~N2 어휘 보충
- 현재 30단어 중 N2 1개, N1 0개 → N1/N2 목표 사용자의 10문항 진단이 다른 급수 단어로 출제됨.

### 6. FSRS '알고있음' 6초 임계치 재검토
- 앞면 예문이 10초에 걸쳐 서서히 선명해지도록 바뀌었으므로(`CardTimingConfig.exampleFadeDuration`), 현재 기준은 다음과 같음:
  - 6초 안에 '정답 보기' → 표제어만으로 떠올린 것으로 보고 정상 등급
  - 6~10초 → 예문 문맥의 도움을 받은 것으로 보고 `hiddenHintAssisted`(재출제)
- 예문 페이드(10초)와 힌트 창(`hintWindowUpperBound` 10초)은 길이가 같도록 테스트로 묶여 있음.
- 실사용 피드백에 따라 `standardGoodUpperBound`를 7.5~8초로 올릴지 결정.

### 7. 레거시 게임 모듈 정리
- `Features/Game/`, `Services/Game/`의 SMS 게임 코드는 메인 탭과 연결이 끊긴 상태. 새 게임 챕터 설계 시 재활용 또는 정리.
